# Модель и админка игр

## Задача

Заменить Prisma-вьюхи `games`/`genres` (читавшие внешнюю БД `nomb_games`) на
настоящую модель в основной БД с переносом всех данных, добавить админку,
поиск по серии, глубокую фильтрацию и до 3 изображений + 1 видео на игру.

Спека: `docs/superpowers/specs/2026-09-11-games-admin-design.md`
План: `docs/superpowers/plans/2026-09-11-games-admin.md` (12 задач, все выполнены)

## Что сделано

### Модель БД

Новые таблицы вместо вьюх `games`/`genres`: `games`, `game_images` (до 3 на
игру, порядок явный), `game_genres` + `genres_on_games` (M2M вместо строки
`"tag; tag"`), `game_series`. FULLTEXT-индекс на `games(title, shortDescription,
description)` — тот же подход, что и у поиска постов.

Миграция `20260911041555_games_model` — вручную дописан `DROP VIEW games` /
`DROP VIEW genres` (Prisma не увидела их в истории миграций, так как они были
созданы не через миграции — как и часть других вьюх/таблиц в проекте).
`prisma migrate diff` после применения не показал новых расхождений сверх уже
известного pre-existing дрейфа (`navigation_items`/`pages`/`clubs`).

### Нормализация данных

- `decodeHtmlEntities` (`src/common/utils`) — HTML-сущности из старой БД
  (`&quot;`, `&lt;`, `&amp;` и т.д.) декодируются на сервере, не на фронте.
- `parseDuration`/`parseYear`/`parsePlayerRange`/`parseAgeWithPlus`
  (`src/games/utils`) — свободный текст («20+ минут», «3-9», «12+», «-») →
  числовые поля.
- `mapGameStatus` — коды статуса `nomb_games.g_status` (-4..1) → enum
  `GameStatus`.
- `extractSeriesBaseTitle` — эвристика группировки в серии (часть названия до
  «:», серия только если группа ≥ 2 игр).

Все пять утилит покрыты юнит-тестами (TDD, RED→GREEN зафиксирован для каждой).

### Перенос данных (`GET /games/migrate`, `JwtAuthGuard`)

Источник — `nomb_games` на том же MySQL-сервере, читается напрямую через
`$queryRawUnsafe` с полными именами `nomb_games.<table>` (отдельный TypeORM-
коннекшн не понадобился — тот же пользователь БД имеет доступ). Обложки и PDF
правил скачиваются со старого сервера (`http://infomania.ru/gamelibrary/...`)
и заливаются через уже существующий `FilesService.uploadImage`/`uploadDocument`
(резайз/webp/hash-дедуп переиспользованы, не продублированы).

Идемпотентно (пропуск по `externalId`), ошибка одной строки не прерывает
остальные — с учётом всех похожих багов, что чинились в этой сессии раньше
(`files`/`posts`/`main-slider`, память `migration-logic-duplicated`).

### Публичный API

- `GET /games` — фильтры: `search` (полнотекстовый), `genres[]` (все
  обязательны), `players` (число игроков попадает в диапазон игры),
  `ageMin`/`ageMax`, `maxDuration`, `yearFrom`/`yearTo`, `seriesId`,
  `availableOnly`. Сортировка по умолчанию — по названию; при поиске — по
  релевантности через MATCH/AGAINST.
- `GET /games/:id` — карточка с `images`, `genres`, `series`, `rulesFile`.
- `GET /games/genres`, `GET /games/series` — справочники.
- «Игры той же серии» — фронт получает `seriesId` в карточке игры и запрашивает
  `GET /games?seriesId=...`.

### Админка (`JwtAuthGuard`)

`POST/PATCH /games`, `POST/PATCH /games/genres`, `POST/PATCH /games/series`.
Картинки/PDF заливаются существующими `/files/upload/image`,
`/files/upload/document`, в игру передаётся `fileId`. Лимит 3 изображения
проверяется в сервисе (`BadRequestException`).

### Заодно (общая инфраструктура)

`toBooleanFulltextQuery` вынесен из `src/posts/utils` в `src/common/utils` —
теперь используется и постами, и играми без дублирования.

## Проверка

- `npx jest` — **32/32** (5 новых спек: `decodeHtmlEntities`,
  `parse-game-fields` × 4 функции, `mapGameStatus`, `extractSeriesBaseTitle`,
  плюс перенесённый `fulltext-query.spec.ts` и всё, что было раньше).
- `npx tsc --noEmit`, `npm run build` — без ошибок.
- `npx eslint` по всем затронутым файлам — новый код чистый; в
  `posts.service.ts` остались только уже известные 6 pre-existing ошибок
  `no-unsafe-*`/`no-unused-vars` в нетронутых методах.
- **Дата-логика миграции** прогнана на боевых данных внутри Prisma-транзакции
  с принудительным откатом (ничего не записано):
  ```json
  { "totalNormalized": 668, "migrated": 668, "skipped": 0, "failed": 0,
    "seriesCreated": 31, "genresLinked": 1649 }
  ```
  668 = 594 из `g_data` + 74 уникальных из `gl_list` — сходится с анализом на
  этапе спеки. После отката: `games` = 0, `game_series` = 0 — подтверждено
  напрямую SQL-запросом.
- **Путь скачивания файлов** (`attachDownloadedImage`/`attachDownloadedRules`)
  проверен отдельно на 2 реальных обложках и 1 PDF правил через полноценно
  поднятый `FilesService` (с реальными MinioService/ImageProcessingService) —
  обложки скачаны, обработаны (ресайз, webp), залиты в MinIO; PDF (5.3 МБ)
  залит как DOCUMENT. Тестовые записи `File` удалены из БД после проверки
  (сами объекты в MinIO не трогались — не критично для dev-окружения).

## Известное ограничение

`npx prisma migrate diff` показывает, что вьюхи `games`/`genres` были созданы
на БД не через отслеживаемые миграции (как и `navigation_items`/`pages`/`clubs`
до этой задачи) — типовой пре-экзистинг паттерн в этом проекте, не новая
проблема.

## Осталось сделать

- **Реальный запуск `GET /games/migrate` ещё не выполнялся** — только dry-run.
  Это ~668 создаваемых игр + до ~1080 HTTP-скачиваний файлов (594 обложки +
  485 PDF правил) — долгая, создающая реальные данные операция. Нужно
  отдельное подтверждение перед запуском на боевых данных.
- Фронтенд не трогался (задача была только про backend) — формат ответа
  изменился (uuid+slug вместо `gm120`, `images`/`genres`/`series` вместо
  плоских полей `cover_file`/`genres`-строки) — фронту потребуется адаптация
  под новую модель (там и так уже готовятся новые компоненты — `GameGallery`,
  `GameSpecs`, `GameRules`, `GameAlsoSee`, страница `/games/[slug]`).
- Идеи на будущее (см. спеку, раздел «Мои идеи»): ручное слияние серий в
  админке, история статусов/местонахождения игры вместо одного поля,
  «похожие игры» по пересечению жанров, рейтинг/отзывы.
