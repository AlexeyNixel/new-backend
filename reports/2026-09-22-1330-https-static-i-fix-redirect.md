# HTTPS для static.infomania.ru + исправление битых картинок

**Период работы:** 2026-09-22

## Проблема

После перевода `alt.infomania.ru` на HTTPS перестали отображаться изображения в постах. Причина: контент постов в БД хранит абсолютные ссылки вида `http://static.infomania.ru/...`. Браузер на https-странице автоматически апгрейдит такие `<img src="http://...">` до `https://` (mixed content autoupgrade) и **не откатывается обратно на http**, если https недоступен. Так как `static.infomania.ru` не имел сертификата/443, апгрейднутые запросы к картинкам проваливались.

## Решение

Включили HTTPS для `static.infomania.ru` тем же способом, что и для `alt`/`api2` — TLS терминируется на nginx (`192.168.0.13`), origin-сервер статики (`192.168.0.41:10001`, похоже на MinIO) остался на обычном http и никак не менялся.

## Побочная проблема и её исправление

`certbot --nginx -d static.infomania.ru` **без флага `--redirect`** всё равно добавил принудительный редирект http→https (похоже, это поведение по умолчанию в установленной версии certbot 5.8.0, если явно не передать `--no-redirect`). Это сломало внутренние вызовы `proxy_pass http://static.infomania.ru/...` из других блоков nginx (`dev`, `alt`, `adminnew`) — они начали получать 301 вместо контента, так как `proxy_pass` не следует за редиректами.

Попытка почтить через `certbot ... --no-redirect` не сработала (certbot посчитал, что сертификат ещё не требует обновления, и не тронул уже применённые правки). Пришлось вручную отредактировать `/etc/nginx/sites-available/default`: убрали блок `if ($host = static.infomania.ru) { return 301 ...}` с `return 404`-заглушкой, вернули нормальный проксирующий `location /` на порту 80 (идентичный тому, что было до certbot, только с явным `listen 80`).

## Результат

- `http://static.infomania.ru/...` — работает без редиректа (нужно для внутренних proxy_pass из других nginx-блоков).
- `https://static.infomania.ru/...` — тоже работает, сертификат Let's Encrypt действителен до **21.12.2026**.
- Картинки в постах на `alt.infomania.ru` снова отображаются.
- Origin static-сервера (`192.168.0.41:10001`) не менялся.

## На заметку на будущее

- **Certbot 5.8.0 на этом сервере по умолчанию включает редирect http→https**, если явно не указать `--no-redirect` СРАЗУ при первом запуске (а не постфактум). Для доменов, у которых есть внутренние http-потребители (другие nginx-блоки с `proxy_pass http://...`), всегда сразу указывать `--no-redirect` при первом certbot-запуске, а не пытаться поправить это следующим вызовом.
- Стоит по возможности со временем переписать контент постов в БД на относительные/https-ссылки для статики, чтобы не зависеть от мixed-content autoupgrade браузера.
