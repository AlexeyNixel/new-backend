# Исправление миграции связей «пост ↔ тег» (`GET /api/posts/migrate/tag`)

## Проблема

Эндпоинт падал с 500. `PostsService.migratePostOnRubric` в цикле вызывал `tagsOnPosts.create` без проверки на существование.

Состояние данных на момент диагностики:

| | Количество |
|---|---|
| Связей в старой БД (`RubricsOnEntries`) | 4858 |
| Связей в новой БД (`tags_on_posts`) | 4738 |
| Из них уже перенесены | 4714 |
| Связей без поста/тега в новой БД | 0 |

Миграцию уже запускали раньше. Первая же существующая пара `(postId, tagId)` давала ошибку уникального ключа (P2002), и цикл обрывался. Поэтому 144 связи так и не переносились. Кроме того, метод ничего не возвращал и выводил весь массив в `console.log`.

## Исправление

`src/posts/posts.service.ts`, метод `migratePostOnRubric`:

- один `createMany` с `skipDuplicates: true` вместо цикла `create`, поэтому повторный запуск безопасен;
- переносится `assignedAt` из старой БД;
- возвращается статистика `{ total, migrated, skipped }`;
- убран `console.log` всех данных.

## Проверка

- `tsc --noEmit`: без ошибок.
- ESLint: одна ошибка в `posts.service.ts:375` (`tags` не используется). Она была и до этих правок, её не трогал.
- Сам эндпоинт не вызывался (нужен JWT). Ожидаемый результат: `migrated ≈ 144`, `skipped ≈ 4714`.
