# Тип события для афиши (поле `category`)

**Дата:** 2026-10-19

## Зачем

На сайте появилась страница афиши `/afisha`: цвет плаката и фильтр зависят от типа события. Раньше тип угадывался по названию, и это давало ошибки. Теперь тип выбирает редактор.

## Что сделано

- `prisma/schema.prisma` — у модели `Event` новое необязательное поле `category` с enum `EventCategory`:
  - `MASTER` — мастер-класс, практикум;
  - `MUSIC` — концерт, музыкальная программа;
  - `GAME` — игра, квиз, квест;
  - `TALK` — встреча, лекция, литературная программа.
- Миграция `prisma/migrations/20261019120000_event_category/migration.sql`:
  `ALTER TABLE events ADD COLUMN category ENUM('MASTER','MUSIC','GAME','TALK') NULL`.
  SQL сверен с `prisma migrate diff` между старой и новой схемой.
- `CreateEventDto` / `UpdateEventDto` принимают `category` (`null` снимает тип).
- `src/event/utils/event-category.utils.ts` — `assertEventCategory`: неизвестное значение даёт 400 с понятным текстом. Глобальной валидации DTO в проекте нет, и без проверки Prisma вернула бы 500.
- Unit-тест `event-category.utils.spec.ts`. Прогон `npx jest src/event`: 2 набора, 5 тестов, все прошли.
- `GET /api/event` и `GET /api/event/:id` отдают поле `category` автоматически.

## Что не сделано / что нужно

- **Миграция к рабочей БД не применена.** При деплое выполняется только `prisma generate`, поэтому её нужно применить вручную: `npx prisma migrate deploy`. Делать это нужно **до** деплоя кода, иначе Prisma будет обращаться к несуществующей колонке.
- **Админка** (`admin.infomania.ru`) — отдельный репозиторий. В форму события нужно добавить выпадающий список «Тип» со значениями выше и передавать его в `POST/PATCH /api/event` полем `category`.
- У существующих событий `category = NULL`. Сайт для них определяет тип по названию.
- Ошибки ESLint в `event.service.ts` (`no-unsafe-*` в методе `migrate()`) были до этой задачи и не исправлялись.
