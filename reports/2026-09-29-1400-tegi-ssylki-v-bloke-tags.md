# Теги-ссылки в блоке `tags` страниц

## Задача

Сделать так, чтобы теги в блоке `tags` на блочных страницах могли быть ссылками.

## Формат данных

Элемент `items` теперь может быть двух видов:

- `string` — старый формат, тег без ссылки (все существующие страницы продолжают работать без миграции);
- `{ text: string; url?: string }` — тег, который становится ссылкой, если задан `url`.

```ts
type PageTagsBlockItem = string | { text: string; url?: string };
```

Тип добавлен одинаково в три проекта:
- backend: `src/page/types/page-block.type.ts`
- frontend: `services/types/page.type.ts`
- frontend-admin: `services/types/page.type.ts`

## Изменения

- **frontend** — `app/components/page-blocks/Tags.vue`: оба формата приводятся к `{ text, url }`. Тег с `url` рендерится через `NuxtLink`: при наведении заливается цветом `primary`, рядом стрелка. Внешние ссылки (`http(s)://`) открываются в новой вкладке с иконкой «наружу», внутренние (`/post/...`) — обычной навигацией. Теги без ссылки выглядят как раньше.
- **frontend-admin** — `app/components/PageBuilder/BlockTags.vue`: вместо списка строк у каждого тега два поля — текст и необязательная ссылка. При открытии блока старые теги-строки превращаются в объекты с пустой ссылкой. После сохранения такие теги хранятся объектами, фронт их поддерживает.
- **Страница `multlaboratoriya-sibirius`** — все 11 тегов-мультфильмов теперь ведут на новости о фильме (пересборка через `temp/mult-page-build.js` и `temp/mult-page-upsert.ts`; перед сборкой скрипт проверяет, что каждая новость существует). Для фильмов 2022 года, у которых нет отдельной новости, ссылка ведёт на новость с их наградами или показами. Поэтому «Катунь» и «Однажды в зимнем лесу» ведут на одну новость, «Легенда о Солнце» и «Город Н» — на другую.
