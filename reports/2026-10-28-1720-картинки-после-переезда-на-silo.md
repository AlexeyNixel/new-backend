# Картинки из админки после переезда на Silo

**Дата:** 2026-10-28

## Что проверено

- **Загрузка через API админки работает.** Тестовый `POST https://api.infomania.ru/api/files/upload/image` из открытой админки → `201`, файл лёг в Silo:
  `/dev/images/2026/10/28/1793182478082-440547849.webp` (+ копия `-w64`). Тестовая запись в медиатеке — `claude-test.png`, id `c75c0416-8359-4d55-897e-10fa4bd03149`, можно удалить.
- Переменные бэкенда в Dokploy верные (`MINIO_ENDPOINT=s3.infomania.ru`, `MINIO_PORT=443`, `MINIO_USE_SSL=true`, бакет `dev`).
- Админка (сборка) берёт картинки с `https://s3.infomania.ru` — превью открываются.

## Причина: сайт берёт `/dev/...` из старого хранилища

| URL | Результат |
|---|---|
| `https://s3.infomania.ru/dev/images/2026/10/28/…440547849.webp` | 200 |
| `https://infomania.ru/dev/images/2026/10/28/…440547849.webp` | **404 NoSuchKey** |
| `https://infomania.ru/dev/images/2026/10/27/…113483948.webp` (перенесённый) | 200, `Last-Modified: 27 Oct 11:49` — дата из **старого** хранилища (в Silo у копии 28 Oct 05:47) |

Ответы на `infomania.ru/dev/...` приходят без `x-powered-by: Nuxt` — их отдаёт внешний nginx (`192.168.0.13`), а не `routeRules` Nuxt. Проксирует он в старый MinIO (`static.infomania.ru` → `192.168.0.41:10001`, см. отчёт `2026-09-22-1330-https-static-i-fix-redirect.md`). Поэтому всё, что загружено после переноса, на сайте даёт 404, а старые файлы по-прежнему открываются.

## Что нужно сделать (на 192.168.0.13, доступа у ассистента нет)

В `server`-блоке `infomania.ru` (`/etc/nginx/sites-available/default`) — `location /dev`, `/site`, `/media`:
- либо убрать их — тогда запросы уйдут в Nuxt, а его `routeRules` уже проксируют в `https://s3.infomania.ru`;
- либо поменять `proxy_pass` на `https://s3.infomania.ru` (с `proxy_set_header Host s3.infomania.ru;` и `proxy_ssl_server_name on;`).

Потом `nginx -t && systemctl reload nginx`. Проверить те же блоки у других доменов (`dev`, `alt`, `adminnew`).

## Попутно исправлено в коде

`MinioService.uploadFile` передавал метаданные как `{ contentType }` — minio сохранял их в `x-amz-meta-contenttype`, а файл отдавался как `binary/octet-stream` с `nosniff`. Заменено на `{ 'Content-Type': mimeType }`. Уже загруженные файлы так и останутся с `binary/octet-stream`: в `<img>` они показываются, но при прямом открытии ссылки скачиваются.
