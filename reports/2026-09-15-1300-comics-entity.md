# Сущность «Комиксы»

## Задача

Новая модель `Comic` в основной БД по образцу `Game`/`Book`, но со своими
полями и без переноса данных (источника нет) — см. спеку и план:
`docs/superpowers/specs/2026-09-15-comics-entity-design.md`,
`docs/superpowers/plans/2026-09-15-comics-entity.md`.

## Что сделано

- **Модель**: `Comic`, `ComicImage` (до 3 изображений, join-таблица с
  `order`), `ComicGenre`/`GenresOnComics` (M2M-жанры), `ComicSeries`
  (группировка — «Марвел», «ДС», «Ван Пис» на одном уровне, без отдельного
  издательства). Специфичные для комиксов поля: `author`, `illustrator`,
  `volumeNumber` (№ тома/выпуска), `ageRating` (необязательное),
  `externalLink`. Без инвентарного статуса — просто каталог, как у книг.
- **Миграция БД** `20260915055115_comics_model` — вручную вычищен посторонний
  дрейф (`navigation_items`), `prisma migrate diff` после применения не
  показал ничего про `comic`.
- **API**: `GET /comics` (фильтры: `search` по названию, `genres[]`,
  `seriesId`, `ageMax`, `yearFrom`/`yearTo`; сортировка — общий механизм
  `sortBy`/`sortOrder`, дефолт `createdAt desc`), `GET /comics/:id`,
  `GET /comics/genres`, `GET /comics/series` — публичные;
  `POST`/`PATCH /comics`, `.../genres`, `.../series` — под `JwtAuthGuard`.
  Поиск — простой `title: { contains }`, без FULLTEXT (сознательно, по
  запросу).
- «Другие тома серии по порядку» — без отдельного эндпоинта:
  `GET /comics?seriesId=X&sortBy=volumeNumber&sortOrder=asc` уже работает
  через общий механизм сортировки.

## Проверка

- `npx jest` — 46/46 (без изменений — для этой сущности новых чистых утилит
  не понадобилось, вся логика — прямые Prisma-запросы, как у `GamesService`).
- `tsc --noEmit`, `npm run build`, `eslint` — чисто.
- Вживую на dev-сервере (JWT, реальная БД):
  - создал жанр «Сэйнэн» и серию «Ван Пис»;
  - создал «Ван Пис. Том 2», затем «Ван Пис. Том 1» (специально в обратном
    порядке вставки) — `GET /comics?seriesId=...&sortBy=volumeNumber&sortOrder=asc`
    вернул именно Том 1, потом Том 2 — сортировка по номеру тома, а не по
    порядку создания;
  - `GET /comics?search=Ван Пис` — нашёл оба тома;
  - `PATCH` с 4 `imageFileIds` — `400 Bad Request` с понятным сообщением;
  - без токена на `POST /comics` — `401`;
  - `PATCH /comics/genres/:id` — переименование жанра сработало.
  - Тестовые данные (2 комикса, 1 серия, 1 жанр) удалены после проверки.

## На заметку

- Тот же артефакт кодировки, что уже встречался в сессии: инлайновый
  `curl -d '...'` с кириллицей в Windows-терминале искажает текст до отправки
  (не баг приложения) — тестовые запросы с кириллицей отправлялись через
  файлы (`--data-binary @file`) с явным UTF-8.
- Фронтенд (публичный сайт и `frontend-admin`) не делался — по спеке это
  отдельный следующий шаг, если понадобится.
